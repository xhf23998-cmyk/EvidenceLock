# EvidenceLock

EvidenceLock 是科研交付物的本地证据链验收工具。它把论文、报告或回复信中的数值陈述，与 CSV、TSV、DOCX、PDF、TXT 和 Markdown 证据文件进行交叉核对。

## 当前能力

- 提取样本量、准确率、F1、AUC、P 值、延迟和实验次数等数值；
- 解析结构化 CSV/TSV 表头、字段和值；
- 归一化百分比、比例、秒/毫秒以及常见单位；
- 根据显示精度应用舍入容差；
- 在多个候选实验无法安全区分时标记“待核实”，避免强行报冲突；
- 展示稿件位置、证据文件、来源行和修改建议；
- 导出 Markdown 核验报告；
- 全部文件在浏览器本地解析，不上传或留存未发表材料。

## 使用边界

EvidenceLock 用于发现值得人工关注的证据缺口，不判断研究真实性，也不替代作者、统计专家、编辑或审稿人的最终复核。

当前版本不支持扫描版 PDF 的 OCR。单个文件上限为 25 MB，证据文件最多 20 个、总计不超过 100 MB。

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm ci
npm run dev
```

开发服务会显示本地访问地址。提交代码前运行：

```bash
npm test
npm run lint
```

## GitHub 发布建议

GitHub 仓库适合保存和公开源码，但这个项目当前使用 Vinext 和 Cloudflare Worker 运行结构，不能直接把仓库当作 GitHub Pages 静态站点。

推荐的免费公开方式：

1. 将本项目推送到 GitHub，使用仓库中的 GitHub Actions 自动运行构建、算法回归测试和代码规范检查；
2. 继续使用现有 Sites 生产站点承载应用；
3. 在准备公开测试时，把站点访问权限从“仅所有者”调整为“公开”；
4. 将公开站点网址放到 GitHub 仓库首页和 About 区域。

这样 GitHub 负责源码、问题反馈和版本管理，Sites 负责真正的网站运行。若必须使用 GitHub Pages，需要先将项目单独改造为纯静态 Vite 应用。

## 持续集成

`.github/workflows/ci.yml` 会在推送和拉取请求时执行：

- 依赖的锁定安装；
- 生产构建；
- 数值归一化与证据匹配回归测试；
- 服务端渲染检查；
- ESLint 检查。
